# Domain Docs

This is a single-context repository.

Before engineering work:

- Read root `CONTEXT.md`.
- Read relevant decisions under `docs/adr/`.
- Use the domain terms from `CONTEXT.md` in specs, issues, tests, and implementation.
- Surface any ADR conflict explicitly instead of silently overriding it.

If a needed domain term does not exist, reconsider the wording or add it through the domain-modeling workflow when the gap is real.

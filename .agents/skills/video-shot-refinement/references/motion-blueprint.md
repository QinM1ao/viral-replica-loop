# 动作蓝图门禁

本文件只处理局部精修中的动作、硬切和视频参考权重。表情眼神由 [脸部状态证据门禁](face-expression-evidence.md) 单独约束。

## 建立蓝图

从原片 RGB 区间量出：

- `shot_count`：内部硬切数加一；
- 每个硬切的真实时间；
- 每个 Shot 的首态、主体、完整移动轨迹、动作峰值和终态；
- 产品、手、头部和身体分别从哪里移动到哪里；
- 是否存在极短过渡镜头。

先用切镜检测定位候选点，再查看候选点前后的原生帧确认。检测器只提供候选，不能替代可见帧。极短硬切镜头仍单独记录，不得因为时长短而并入相邻动作。

当用户指向“之前成功的版本”时，绑定那条真实视频和请求文件，直接检查动作与切镜；目录名、旧报告或“成功”状态只证明任务完成，不能证明动作通过。

完成条件：每个源 Shot 都有唯一时间段、可见动作轨迹和终态；所有硬切都由原生帧确认。

## 验证深度参考

深度视频应与动作蓝图具有相同：

- 时长、画幅和帧率关系；
- Shot 数量、顺序和硬切位置；
- 人物、产品和双手的大幅轨迹；
- 动作峰值与终态。

若深度视频已保留这些事实，而生成结果变成静止展示、漏镜头或改轨迹，问题位于提示词权重或生成执行，不得把责任归到素材。

完成条件：深度视频覆盖蓝图里的每个 Shot、硬切和动作峰值。

## 绑定提示词

多镜头 source-locked 精修将 `@视频1` 定义为“动作、镜头顺序和节奏参考”，各份素材只负责自己的明确职责，并写明：

1. 从第一帧到最后一帧控制真实 Shot 数量和硬切顺序；
2. 控制主体、产品和双手的完整轨迹、速度、动作峰值与终态；
3. 静态图片分别传递身份、场景、光线或产品外观；
4. 最终可见动作按已经核实并写入 Prompt 的逐 Shot 事件脚本执行。

时间轴 Shot 块必须与动作蓝图数量、顺序和边界一致。Shot 文字解释视频中的可见动作，不重新设计动作。核心轨迹使用正向可见结果，例如“手持喷瓶从脸前一侧横扫到另一侧并覆盖全脸”。

压缩素材定义时，`Shot 数量 / 硬切 / 完整轨迹 / 视频参考职责` 是不可删的最小信息。删除其中任何一项都属于控制行为变化，不是文字精简。

完成条件：提示词中的每个 Shot 唯一绑定一个蓝图 Shot；没有漏掉极短镜头；视频参考职责和每个核心轨迹均可直接找到。

## 与表情协同

动作和表情是两条同时存在的证据链。强化动作时保留已经通过的 Shot-local 表情 cue；修表情时不改 Shot 数量、硬切或动作轨迹。

素材定义压短后，检查剩余 cue 的显著性。一个高度具体的眼睑动作若成为全段唯一细节，容易被放大执行；改为“基线状态 → 动作节点的短变化 → 返回基线”，并保留动作蓝图。

完成条件：动作蓝图没有因表情修复而变化，表情 cue 也没有因动作修复而消失。

## 生成后验收

先按动作蓝图检查：

- 实际 Shot 数量与顺序；
- 每个硬切是否存在，极短镜头是否保留；
- 第一帧是否已经进入源动作；
- 产品、手和头部是否走完相同方向与范围；
- 动作峰值和终态是否出现；
- 是否被静态参考改成停顿、定点展示或额外摆姿。

切镜检测和光流可作为快速预警；最终结论仍以原片和生成片的同时间帧为准。漏硬切、漏动作、方向错误或明显静止化均为动作 `FAIL`，不能因音视频技术 QC 通过而提升。

完成条件：动作蓝图中的每个 Shot、硬切、轨迹、峰值和终态在生成片中逐项有可见证据。

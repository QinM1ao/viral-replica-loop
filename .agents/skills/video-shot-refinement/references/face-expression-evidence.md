# 脸部状态证据门禁

本文件只处理局部精修的证据选择；预算和单人/多人路由以 [表情提示预算](../../video-replication/references/expression-prompt-budget.md) 为准。

## 路由

- 已有同源 `expression_prompt_profile.json`：直接复用。
- 多人或人物身份不确定：使用 profile 中同一次视频理解的 `expression_and_gaze`，不运行眨眼检测。
- 单人、当前失败项确为眼神表情且同源缓存缺失：运行一次 `tools/run_face_expression_detector.py`。该入口固定使用项目本地环境；依赖或检测失败是 `STOP`，人工帧描述不能替代检测时间线。

纯灰度深度、静态人物图、场景图和生成片不能充当原片表情证据。检测不到人脸或 RGB 与数值冲突时，记录不确定并省略 cue；不再调用视频理解模型。单人原片人脸覆盖充分但可靠眨眼事件为零时，执行主流程表情预算中的“无眨眼兜底”，把检测到的缺席证据与选中的动作节点一起绑定。

## 选择

按源片实际含脸节拍选择短 cue，按顺序判断：

1. 当前生成结果存在错误首态时，纠正首帧眼睛状态；
2. 保留有动机的注视或常规表情变化；
3. 动作确有需要时，加入与喷雾、转头或停顿绑定的自然眨眼。

不设“15 秒最多几次眨眼”或“每 Part 最多几条 cue”。同一节拍出现连续眨眼时用一句自然语言概括，避免逐次罗列；原片没有可靠眨眼时，可在动作释放、视线回落或转头稳定节点加入短促自然眨眼。目标是消除呆板，不是覆盖全部眼睑事件。

用“基线状态 → 动作节点的短变化 → 返回基线”写 cue。睁眼为基线时先写自然睁眼，再写眼睑短暂轻合，最后写立即恢复自然睁眼；只有原片首帧确实闭合时才把闭眼写成首态。这样既保留表情节拍，也避免把一个正向闭眼词扩展成整段持续闭眼。

动作参考、素材定义或全局段落被压缩后，重新检查 cue 的显著性。一个高度具体的眼睑动作若成为整段唯一细节，改写成上述三态短句；不得通过删除所有表情 cue 来修动作，也不得为了修表情改变 Shot 数量、硬切或动作轨迹。

正向短句示例：

```text
自然睁眼为基线；喷雾经过时眼睑短暂轻合，随即恢复自然睁眼。
```

## PASS

- `expression_cue_source` 能指向同源 profile、RGB 证据或用户明确要求；
- cue 通过 `rules/EXPRESSION_PROMPT_POLICY.json` 的长度和分句预算；
- 多人 cue 不含眨眼、闭眼、睁眼或眼睑指令；
- cue 合并进 `画面：`，没有独立 `表情：`；
- cue 写明基线、短变化和返回，且没有被动作修复删除；
- Shot 数量、硬切和动作轨迹没有因表情修复而变化；
- 本轮没有新增视频理解调用。
